### How to run
```bash
docker start oracle19c          # wait until healthy (~1 min)
bun install
bun run typecheck
bun run test:coverage           # against the MIRA schema (.env APP_DB_*)
bun run sim                     # against the MIRA_SIM schema (.env MIRA_SIM_DB_*)
docker stop oracle19c
```
- **Simulation schema:** `MIRA_SIM`, created once with `sim/setup-schema.sql` (see the README "Simulation" section). Its credentials are in `.env` as `MIRA_SIM_DB_USERNAME` / `MIRA_SIM_DB_PASSWORD`.
- **Safety:** the simulation drops and rebuilds its `SIM_*` objects on every run, and refuses to run against `MIRA` or the app schema.
- **Test schema:** `MIRA` needs `QUOTA UNLIMITED ON USERS`, which was already granted.

### Where things are documented
- `README.md`: the API, including Expressions, Row Pattern Matching, Joins and Trees, Recursive CTEs, Series, Testing and Simulation.
- `sim/RESEARCH.md`: the Oracle 19c catalog, 35 accounting and 33 inventory patterns, the capability map, the full defect log and the gap history.
- `docs/ROADMAP-2.1.md`: the ORM comparison and the 2.1 plan.

### Known issues and things to remember
- **Flaky test:** the chaos test "pool recovers after saturation" sometimes fails on a Docker database that has just been under heavy load. `main` behaves the same way. It is timing, not code.
- **Time zones:** `bun test` always runs with `TZ=UTC`, which hides time-zone bugs. The simulation runs in the real local zone, which is how the `$now` defect was found.
- **Thick mode:** with oracledb 7, Thick mode needs Oracle Client 19c or later. Development on the Mac runs in Thin mode.
- **Loan payment:** in the simulation, the loan schedule takes the monthly payment as an input, because Mira has no `$pow`.
- **`set` limits:** `withRecursiveCTE` `set` can only compute columns of the anchor table. An empty `joinOn` must have a `while`.

## 3. CATHERINE

### What changed: 1.0.0-dev.54 (PR #16, merged)
- **Wrapper:** CATHERINE's copy was byte-identical to Mira's starting point, so Mira 2.0's wrapper was copied in as is, with all 43 fixes and every new feature.
- **Adapter:** merged **three-way**, so CATHERINE's metrics store, watchdog and `RetryPolicy` are untouched. It brings in:
  - the money-safe `fetchTypeHandler`, applied driver-wide
  - a `callTimeout` reset before a connection goes back to the pool
  - `isPoolHealthy` returning false after `closeAll`
- **One deliberate difference:** connection acquire no longer retries **NJS-040** (pool queue timeout). The shared `RetryPolicy` still treats it as transient for other callers, such as batch work.
- **Message templates:** three templates now show the refused value (`COLLECTION_INVALID_TABLE_NAME`, `INVALID_ROW_COUNT`, `WINDOW_INVALID_ARGUMENT`). That follows CATHERINE's rule that a template's arguments appear in its output, and the same change went into Mira.
- **Tests:** 6 tests that pinned the old behaviour were updated:
  - a large `$in` of one type is now one collection bind
  - the `$now` SQL
  - the message snapshot

### Release convention (as followed for dev.53 and dev.54)
1. Commit the change. Then make a separate `chore(release): 1.0.0-dev.N` commit that:
   - bumps **both** `Backend/package.json` and `Frontend/package.json`,
   - adds a changelog entry through `ChangelogModel.create` (it writes `data/changelog.enc`),
   - runs `bun run changelog:dump`, which refreshes `scripts/changelog-dump.json`.
2. Check: `bun scripts/verify-changelog-release.ts --ref HEAD --tag v1.0.0-dev.N`.
3. Work on a branch, open a PR, merge into `main`.

### Not done yet
- **oracledb 7 upgrade:** CATHERINE is still on oracledb 6.10; Mira is on 7.0.1. This should be its own change, since Thick mode then needs Oracle Client 19c or later and the compiled `.exe` uses Thick mode.
- **Integrity registry:** empty in the template by design (`Object.freeze({})`). Each app registers its own tables, so the integrity sweep endpoints have nothing to check until an app adds tables.

## 4. Keeping the shared wrapper in sync

1. **Change Mira first.** Write the failing test first, then fix or build. Run `test:coverage` and `sim` against the live database.
2. **Copy to CATHERINE:**
   - Copy `src/utils/oracle-mongo-wrapper/**` and `src/constants/messages/oracleWrapper.messages.ts` as is. They are identical today.
   - Bring the adapter (`src/config/adapters/oracle.ts`) over with a **three-way merge** (`git merge-file`). CATHERINE's adapter has its own metrics, watchdog and `RetryPolicy` code, and Mira's has an inlined classifier instead. Never copy the adapter file over.
3. **In CATHERINE:**
   - Run typecheck, lint and test.
   - Update any tests that pinned old behaviour.
   - Check the message-template test, which requires each template's arguments to appear in its output.
   - Release as the next `dev.N`.
